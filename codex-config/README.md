## 3 分钟搞懂全局：Codex 底层机制全貌

在深入细节前，我们先建立对 Codex 运行时（Runtime）的“正常人类心智模型”：

```
                    ┌─────────────────────────────────────────────────────────────┐
                    │               用户电脑 (Windows / Codex Client)             │
                    └─────────────────────────────────────────────────────────────┘
                                                   │
   1. 读取全局配置 (~/.codex/config.toml)            │ 2. 扫描并加载上下文
      - model / verbosity / sandbox               │    - 工具注册列表 (Tools: bash, exec, edit...)
      - model_instructions_file (替换基础指令)      │    - 技能目录 (Skills: 扫描所有 .agents/skills)
      - developer_instructions (追加开发指令)       │    - 权限与审批策略 (Permissions)
                                                   │    - 桌面运行时状态 (App Context)
                                                   │    - 项目与个人规则 (AGENTS.md / AGENTS.override.md)
                                                   ▼
                    ┌─────────────────────────────────────────────────────────────┐
                    │               组装成底层请求 Payload (JSON)                  │
                    │                                                             │
                    │  [role: developer]                                          │
                    │   ├─ 结构化工具定义 (~11,500 tokens)                          │
                    │   ├─ 基础提示词 "You are Codex..." (~4,150 tokens)           │
                    │   ├─ 技能描述清单 (Skills Catalog, ~4,650 tokens)             │
                    │   ├─ 桌面上下文与权限 (~2,500 tokens)                         │
                    │   └─ [可选] 用户追加的 developer_instructions                │
                    │                                                             │
                    │  [role: user]                                               │
                    │   ├─ 项目规则 AGENTS.md / 环境上下文 (~900 tokens)           │
                    │   └─ 用户真实输入的文字 (比如 "hi", 仅 6 tokens!)             │
                    └─────────────────────────────────────────────────────────────┘
                                                   │
                                                   ▼ 发送给模型 (gpt-6-astra)

```

## 核心结论速查（TL;DR）

### 1. 提示词定制的两个核心配置项
* **追加个人/团队规则（最推荐、最安全）**：
  在 `~/.codex/config.toml` 顶层设置 `developer_instructions = """你的规则"""`。它会在官方提示词后面**追加**一段指令，既保留官方工具规范，又能按需注入风格与约束。
* **整份替换基础指令（高级用法、需谨慎）**：
  在 `~/.codex/config.toml` 顶层设置 `model_instructions_file = "路径/到/model-instructions.md"`。它会**彻底覆盖**官方约 2.1 万字符的基础提示词。千万不要只写两三行，否则模型将失去官方针对工具调用、多步推进与任务闭环的核心指导。

### 2. 为什么发一句 `hi` 吃了 2.45 万 Tokens？
* 真实抓包表明：Codex 的客户端开销极其庞大。
* **工具定义**占了近 **47%**（约 11,478 tokens）；
* **技能描述清单**占了近 **19%**（约 4,650 tokens）；
* **基础提示词**占了约 **17%**（约 4,152 tokens）；
* 用户输入的真实内容只有 **6 tokens**，相当于 99.9% 的上下文都是 Codex 运行框架自身的支撑信息（注：现代模型支持 Prompt 缓存，计费以缓存命中后实际费用为准）。

### 3. 技能去重：Git 忽略完全无效！
* 如果你在项目的根目录和 `.agents/skills/private/` 下有同名技能，即便在 `.gitignore` 或 `.git/info/exclude` 中忽略了 private 目录，**Codex 仍然会照常扫描并把它打包进请求**！
* 结果就是同名技能在提示词里出现多次，浪费 token 且容易造成模型混乱。
* **正确的去重方式**：在 `config.toml` 中配置 `[[skills.config]]`，显式指定 `path` 并将 `enabled` 设为 `false`。

### 4. 2026-09-24 配置清空惨案的教训
* 抓包工具在未隔离 `CODEX_HOME` 的情况下双开了 Codex 桌面实例；
* 两个进程并发抢占同一个 `~/.codex` 目录和沙箱锁，导致主配置文件被简化的临时状态覆盖清空；
* **保命原则**：动配置前先备份；抓包/调试时切勿共用主实例配置目录。
