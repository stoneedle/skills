# Codex 提示词配置与深度定制指南

> **导读**：很多开发者想定制 Codex 的行为（比如强制中文回答、先给结论再给方案、遵循自己的代码风格、减少不必要的反问），但在翻阅官方文档或网络零散资料时往往一头雾水：**到底改哪个文件？写在什么位置？写了为什么不生效？改了之后会不会把内置功能改坏？**  
> 本文用大白话彻底讲清 Codex 提示词的运作机制与最佳实践。

---

## 核心心智模型：Codex 的提示词是怎么组成的？

每次你在 Codex 里提问时，发送给模型的提示词并不是单一的长文本，而是**积木式拼装**起来的：

```
Codex 组装后的完整 Prompt
│
├── [developer 角色] 基础指令 (Base Instructions) 
│   └── 官方内置的 "You are Codex, a coding agent developed by OpenAI..." (约 21,400 字符)
│       └── 掌控工具调用、任务推进、代码编辑、PR 输出等基石逻辑。
│
├── [developer 角色] 额外追加指令 (developer_instructions)
│   └── 【你完全掌控】在 config.toml 中配置，适合写个人偏好、工程决策规则。
│
├── [developer 角色] 运行时注入 (Runtime Context)
│   └── 桌面当前状态、工具列表 (Tools)、技能清单 (Skills Catalog)、权限说明 (Permissions)。
│
└── [user 角色] 项目指导 (AGENTS.md) 与你的对话
    └── 【你完全掌控】你项目里的 AGENTS.md / AGENTS.override.md，以及你输入的具体问题。
```

官方经实测验证最直接、最关键的配置入口有两个：
1. **追加指令 (`developer_instructions`)**：最推荐、最安全。
2. **替换基础指令 (`model_instructions_file`)**：高级玩法，整份替换官方基础段。

## 方案一：追加自定义规则（强烈推荐，日常首选）

如果你只想让 Codex：
* 默认讲中文；
* 先给结论，再讲原理，代码保持优雅简洁；
* 减少过度确认，常规小改动自主推进；
* 遵守团队的架构规范（如单一事实源、窄接口）；

**请使用 `developer_instructions` 顶层配置项。**

### 配置方法

打开你的用户配置文件：`C:/Users/stoneedle/.codex/config.toml`（或你的项目级配置文件 `<项目>/.codex/config.toml`）。

在文件的**最上方（第一个 `[xxx]` 表之前）**添加如下内容：

```toml
developer_instructions = '''
# 个人协作规范

1. 语言与表达：
   - 默认使用简体中文回复，语气专业、直接、克制，禁止空话套话。
   - 采用“结论先行”原则：先给出明确答复或改动方案，再附带必要的技术分析与证据。

2. 任务自主推进：
   - 对于明确、低风险、可逆的常规改动（如修复已知 bug、小范围重构、完善注释等），直接自主推进完成，不要反复询问停顿。
   - 只有涉及架构颠覆、破坏性变更、敏感数据且现有证据无法决定的关键取舍时，才停下来请求确认。

3. 工程代码规范：
   - 严格遵守深模块、窄接口设计原则，保护已有无关代码不受污染。
   - 保证单一事实源，杜绝在不同地方重复定义相同逻辑。
   - Windows 环境下注意路径转义与 UTF-8 编码。
'''
```

### 为什么推荐这种方式？
* **保留官方底座**：它是在官方约 2.1 万字符的基础指令**后面追加**一段文字。基础工具编排依然由官方维护，同时融入你自己的偏好与规范。
* **随时微调**：想加一条规则就加一条，删掉某条也不影响系统正常工作。

### 踩坑预警（重要！）
> [!CAUTION]
> **TOML 语法陷阱：必须写在第一个 `[table]` 之前！**  
> TOML 文件的语法规则是：顶层键值对必须写在所有 `[xxx]`（如 `[windows]`、`[features]`）之前。如果你随手把 `developer_instructions = ...` 粘贴到了文件末尾，它就会被误解析为最后一个子表的字段，导致配置无法作为全局指令生效！

> [!WARNING]
> **没有 `developer_instructions_file` 这种配置项！**  
> Codex 并没有提供通过外部文件引入追加指令的键名，追加指令只能直接作为字符串写在 `config.toml` 中。

## 方案二：整份替换基础指令（高级玩法，谨慎使用）

有些极客开发者觉得官方那约 2.1 万字符的基础指令太啰嗦，或者想从根源上改变 Codex 的所有决策流程（比如彻底去除某些官方冗余限制）。

官方提供了 `model_instructions_file` 这一配置项。

### 核心机制：它是“100% 覆盖”，不是追加！
当你配置了 `model_instructions_file`，Codex 会**直接扔掉**官方内置的约 2.1 万字符 `You are Codex...` 基础指令，换成你指定文件的全部内容。

> [!CAUTION]
> **千万不要在指定文件里只写两句个人偏好！**  
> 如果你新建一个 `my-rules.md`，里面只写了“请用中文回答”，然后把它配进 `model_instructions_file`，Codex 会把官方针对工具调用规范、代码编辑保护、Git 分支处理、PR 描述生成等数万字的关键行为指导全部剔除！模型虽然名义上还有工具定义，但在复杂工程中极易表现失常、甚至失去闭环推进能力。

### 正确的配置步骤

1. **获取官方纯净基线文件**：  
   我们已经为你从真实的 `gpt-6-astra` 模型请求中无损提取了官方原版基础指令，保存在：  
   [提示词配置与参考原文/model-instructions.base.md](提示词配置与参考原文/model-instructions.base.md)（共 21,420 字符）。

2. **复制并修改**：  
   将该文件复制一份为你的定制文件（例如 `model-instructions.custom.md`）。在保留其绝大部分工具规范、自治流程的前提下，修改你想要改动的章节（例如修改测试策略、审批策略等）。

3. **配置到 `config.toml`**：  
   在 `C:/Users/stoneedle/.codex/config.toml` 最上方（第一个表之前）写入：

```toml
model_instructions_file = "C:/your-config/prompts/model-instructions.custom.md"
```
*(把示例路径改为第 2 步实际编辑的 custom.md 的绝对路径；路径建议使用正斜杠 `/`。不要继续指向未修改的 base.md。)*

4. **重启 Codex 并在新会话中验证**。

## 方案三：项目级规范（AGENTS.md 与 AGENTS.override.md）

除了全局系统级的 Prompt，Codex 还支持针对某个具体的代码仓库配置个性化指令。

### 工作机制
* Codex 会在每个请求中，作为 `user` 角色的一条前置上下文，把当前项目的 `AGENTS.md` 内容带上（通常占 300~500 tokens）。
* 它主要用于交代当前项目的背景、技术栈、启动命令、目录规范。

### AGENTS 的层级与“覆盖机制”
* **全局规则**：`~/.codex/AGENTS.md`（适用于这台电脑上的所有项目）。
* **项目规则**：`<项目根目录>/AGENTS.md`。

> [!IMPORTANT]
> **致命陷阱：`AGENTS.override.md` 的霸权机制**  
> 如果一个目录下同时存在 `AGENTS.md` 和非空的 `AGENTS.override.md`，Codex **只会加载 `AGENTS.override.md`，而会 100% 彻底忽略旁边的 `AGENTS.md`**！  
> 在之前的实测排查中，多次出现“用户明明在 `AGENTS.md` 里改了东西，但模型根本不认”的情况，最后发现该目录下躺着一个 `AGENTS.override.md`。

### 敏感信息红线
抓包排查中曾发现：有项目的 `AGENTS.override.md` 中直接明文写了本地测试用的账号和数据库密码！  
虽然方便了模型自动登录测试，但这意味着：
1. 你的密码会在**每一次对话**中都被发送给远端大模型；
2. 抓包、Trace、本地日志中会永久沉淀明文密码。  
**最佳实践**：AGENTS 里只写“测试凭证的获取方式或环境变量名”，绝不直接写明文账密。

## 总结：我到底该怎么选？

| 你的需求 | 推荐方案 | 改动文件与语法 | 风险等级 |
| :--- | :--- | :--- | :--- |
| 想要中文、简洁、少废话、特定编码风格 | **方案一：追加指令** | `config.toml` 顶层加 `developer_instructions = """..."""` | 零风险（极力推荐） |
| 想为特定项目配置构建命令、接口规范 | **方案三：项目规范** | 在项目根目录维护 `AGENTS.md`（注意防 override） | 零风险（极力推荐） |
| 想深度大改 Codex 的自治与工具决策基石 | **方案二：基础指令替换** | 基于 `model-instructions.base.md` 微调后配置 `model_instructions_file` | 高风险（需全面回归测试） |

### 修改后的验证与回滚步骤

1. **测试生效**：修改 `config.toml` 后，必须**完全退出并重启 Codex**。请新开一个测试对话验证，不要在既有历史会话中验证（旧会话可能有历史上下文干扰）。
2. **一键回滚**：如果发现模型行为异常：
   - 方案一：直接在 `config.toml` 中删掉或注释掉 `developer_instructions`；
   - 方案二：删掉或注释掉 `model_instructions_file`；
   - 重启 Codex 开启新会话，即可恢复官方默认状态。
