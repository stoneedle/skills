# Codex 技能系统机制与重复加载避坑指南

> **一句话导读**：你在 `.gitignore` 里明明排除了旧技能目录，或者在 `AGENTS.md` 里千叮咛万嘱咐“只读 private 目录”，为什么抓包发现 Codex 每次还是把新旧两份技能都塞进了请求里？  
> 本文剖析 Codex 技能发现的底层机制，并提供一行行可落地的精准去重方案。

---

## 现象还原：一次真实的技能翻车现场

在对 `xby` 项目（`D:/workSpaces/jxd/xby`）的请求抓包中，我们发现模型收到的技能目录（Skills Catalog）里躺着 **49 个技能条目**。

但仔细一查技能名称，发现**真正不同的技能只有 44 个**，其中有 4 个技能发生了严重的重复加载：

| 重复的技能名称 | 在请求中实际出现的路径 | 出现次数 | 造成的后果 |
| :--- | :--- | :---: | :--- |
| `hussar-auto-dict` | ① `.agents/skills/hussar-auto-dict/`<br>② `.agents/skills/private/hussar-auto-dict/` | 2 次 | 浪费上下文；模型难以分辨该用哪个 |
| `hussar-auto-flow` | ① 项目同名根目录<br>② 项目 private 目录 | 2 次 | 新旧工作流定义打架 |
| `hussar-auto-resource` | ① 项目根目录<br>② 项目 private 目录<br>③ 用户全局目录 `~/.agents/skills/` | **3 次** | **极其严重**：三个版本的实现逻辑差异巨大（有的走 SQL 注册表，有的走直接脚本） |
| `lims-ui-docs` | ① 项目根目录<br>② 项目 private 目录 | 2 次 | 重复占位 |

这不仅凭白增加了不必要的上下文占用，更危险的是：**不同路径下的同名技能，代码实现很可能存在差异！** 模型在选择技能时极易产生混淆，导致调用了非预期的过时版本。

---

## 为什么会重复？两大直觉误区剖析

很多工程师在试图解决这个问题时，都踩了以下两个误区：

### 误区一：“我在 `.gitignore` 里忽略了，Codex 就不应该读它”
* **直觉想法**：把 `.agents/skills/private/` 加到 `.gitignore` 或 `.git/info/exclude` 里，Git 都不管了，Codex 肯定也不会读。
* **残酷真相**：**Codex 的技能扫描器完全不理会 Git 忽略规则！**  
  Codex 在启动时是从文件系统层面直接遍历支持的技能搜索路径的。只要相关目录下存在合法的 `SKILL.md`，它就会直接抓取，根本不管 Git 有没有忽略。

### 误区二：“我在 `AGENTS.md` 里要求模型只看 private 目录就行了”
* **直觉想法**：在 `AGENTS.override.md` 里写一句话：“*本项目所有技能统一使用 private 目录下的版本，忽略其他版本*”。
* **残酷真相**：**自然语言指令管不住技能目录加载！**  
  `AGENTS.md` 是发给大模型的行为指导；而“技能发现（Skill Discovery）”是 Codex 客户端在发请求前就已经完成的预处理步骤。哪怕你在规则里写了一万遍，Codex 依然会把两份技能目录统统打包进请求体。

### 机制设计规则：同名技能不会自动合并
当搜索路径中存在多个同名但路径不同的技能时，Codex **不会自动去重或覆盖**，而是全部罗列在技能列表中提供给大模型。

---

## 正确解法：在 `config.toml` 中显式禁用冗余技能

要在保留本地文件的同时彻底解决重复加载，应当使用 Codex 原生的配置项：`[[skills.config]]`。

### 操作步骤

打开你的项目级配置文件（推荐）：`D:/workSpaces/jxd/xby/.codex/config.toml`  
*(如果是全局重复，也可以写在用户级配置 `C:/Users/stoneedle/.codex/config.toml` 中)*

在配置文件中加入精准禁用片段（只禁用不需要的旧版/全局版，保留项目专属的 `private` 版）：

```toml
# ==============================================================================
# 技能精准禁用配置（消除重复加载）
# ==============================================================================

# 1. 禁用根目录旧版 hussar-auto-dict，保留 private 版本
[[skills.config]]
path = "D:/workSpaces/jxd/xby/.agents/skills/hussar-auto-dict/SKILL.md"
enabled = false

# 2. 禁用根目录旧版 hussar-auto-flow，保留 private 版本
[[skills.config]]
path = "D:/workSpaces/jxd/xby/.agents/skills/hussar-auto-flow/SKILL.md"
enabled = false

# 3. 禁用根目录旧版 hussar-auto-resource
[[skills.config]]
path = "D:/workSpaces/jxd/xby/.agents/skills/hussar-auto-resource/SKILL.md"
enabled = false

# 4. 禁用用户全局同名 hussar-auto-resource（避免影响本项目专属流程）
[[skills.config]]
path = "C:/Users/stoneedle/.agents/skills/hussar-auto-resource/SKILL.md"
enabled = false

# 5. 禁用根目录旧版 lims-ui-docs，保留 private 版本
[[skills.config]]
path = "D:/workSpaces/jxd/xby/.agents/skills/lims-ui-docs/SKILL.md"
enabled = false
```

## 避坑指南：不要使用错误的替代开关

不要尝试用以下不匹配的开关来去重：

1. **`allow_implicit_invocation: false`**：  
   这是控制技能是否允许模型隐式（自主）调用的开关，**只能控制技能在 Prompt 目录中的展示与调用策略，无法按文件路径进行精确去重**。
2. **`skills.max_context_tokens`**：  
   该项属于实验性预算限制，粗暴截断的方式不仅无法精确挑选保留哪个版本，反而容易误杀正常技能。

---

## 验证与验收标准

配置完成后，按以下步骤验证是否真正生效：

1. **重启 Codex 桌面版**（必须完全退出重进，确保扫描器重新遍历）。
2. 在对应项目中新建一个对话。
3. 观察效果：
   - 技能列表中，上面 4 个技能各自只保留唯一的预期版本；
   - 成功消除冗余的同名条目，避免潜在调用冲突并节省常驻上下文。
